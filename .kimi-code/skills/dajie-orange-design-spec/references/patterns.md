# Pattern 层 · 布局变体登记

> 这一层解决的是「一整块布局怎么排」，不是颜色也不是单个零件。
> 新增布局变体必须登记在本文档，否则它只是散落的 HTML，不算规范。

## 1. 为什么需要这一层

AI 生成界面的漂移，最常发生在布局层。原因很简单：给一段文字描述，AI 只能「理解后重写」；每次重写都是一次重新猜测，必然有偏差。

解决办法不是把描述写得更细，而是**改变动作性质**：从「生成」变成「复制 + 替换数据槽位」。

- 颜色圆角 → 走 token，AI 不需要创作
- 单个组件 → 走 `.btn-primary` 这类既有类名，AI 不需要创作
- 整块布局 → **必须有母版文件可抄**，AI 才不需要创作

## 2. 三层分工

| 层 | 载体 | 管什么 | 改动的影响面 |
|---|---|---|---|
| **Token** | `assets/design-tokens.css` | 颜色、圆角、间距、阴影、字体 | 全局，所有页面所有变体 |
| **Primitive** | `assets/design-tokens.css`（`.btn-*` `.card` `.table` …）<br>`references/components.md` | 单个零件的样式与状态 | 用到该零件的所有位置 |
| **Pattern** | `assets/patterns.css` + `tools/variants/*.html` + **本文档** | 一整块布局的结构与排布 | 只影响引用它的页面 |

预览总览页（`tools/设计规范总览.html`）同时在管三层：Token 调参抽屉改第一层，组件板块看第二层，变体板块看本层。

## 3. 一个变体资产由三部分组成

| 部分 | 放在哪 | 作用 | 复用时要做什么 |
|---|---|---|---|
| **样式** | `assets/patterns.css` 里 `.v-<变体名>` 段 | 唯一来源，只允许用 `var(--token)` | 引一次 CSS，全项目共用 |
| **结构** | `tools/variants/<变体名>.html` 中被注释标出的 `<section>` | 可复制的骨架 | 整段复制，替换数据槽位 |
| **契约** | 本文档 §4 登记表的那一行 | 说明何时能用、何时不能用 | 必须先读，再决定用哪个 |

三者缺一不算规范：只有 HTML 没样式 → 别人复制走样；只有样式没结构 → AI 还得自己猜；没有契约 → 会被套到不该用的场景。

## 5. 新增变体的标准流程

1. **先判断该不该新建**
   现有变体改一改能不能满足？能就改现有变体并升版本，别造第二个近似的。两个长得像的变体比没有变体更糟。

2. **写样式到 `assets/patterns.css`**
   前缀必须是 `.v-<变体名>`，内部用 `__` 分部件。**所有取值来自 `var(--token)`**，不许出现 `#EE6402` 这类硬编码。

3. **写结构到 `tools/variants/<变体名>.html`**
   用 `<!-- 可复用片段：从这里开始复制 -->` 标出边界，根元素带 `data-variant` 与 `data-version`。

4. **登记到本文档 §4**

5. **重新生成总览页**：`python3 tools/build-spec.py`，在浏览器打开 `tools/设计规范总览.html` 确认
   - 脚本会自动扫 `tools/variants/*.html`，从登记表取 P 编号与适用说明
   - 变量没定义、文件缺 `<section>` 都会在输出里报警

6. **过验收**
   - 在 1280 / 768 / 375 三个宽度各看一遍（总览页里变体是内联的，直接用浏览器缩窗口）
   - 临时改一下右下角调参抽屉里的 `--brand`，确认变体整体跟着变 —— 这能立刻暴露硬编码

## 6. 三种复用方式

### 6.1 人复用（复制）

业务项目里：

```html
<link rel="stylesheet" href="design-tokens.css">
<link rel="stylesheet" href="patterns.css">
```

然后把变体文件里注释标出的 `<section>` 整段抄过去，只改文字和少量结构（增删字段）。

### 6.2 AI 复用（硬规则）

写进 `SKILL.md` 的硬规则，优先级高于一切：

1. 需要布局时，**先查 §4 登记表**，找到匹配的变体
2. **读** `tools/variants/<变体>.html` 的完整内容
3. **复制**那段结构，只替换文案、数量、字段名
4. **禁止**凭描述重新发明布局；登记表里没有匹配项时，先问用户，不要自创

这条规则是「AI 无法百分百复刻」的唯一有效解药：不是让 AI 画得更准，而是让它不必画。

### 6.3 代码复用（框架内）

React / Vue 项目把变体抽成组件，**样式仍然只来自 `patterns.css`**，组件里不写颜色：

```jsx
// React 示例：结构包一层，样式全部来自规范
function FormTwoCol({ title, hint, fields, onSubmit }) {
  return React.createElement('section', { className: 'v-form2' },
    /* … 与 variants/form-two-col.html 完全一致的 DOM 结构 … */
  );
}
```

组件文件里出现任何 `#EE6402` 或 `border-radius: 12px` 都算违规 —— 那说明样式没进规范。

## 7. 硬规则

1. 变体类名必须是 `.v-<变体名>` 前缀，禁止占用全局通用类名（`.form`、`.list` 之类）
2. `patterns.css` 内**禁止硬编码色值 / 圆角 / 阴影**，一律 `var(--token)`
3. **改动已有变体必须升版本号**，并在 §4 登记表更新版本列
4. 不要直接改别人已在用的变体：需要变体时新建 `v-<原名>-b`，老页面继续用旧的
5. 「不适用」一列必须写。空着 = 会被用到不该用的地方
6. 变体文件里除被标注的 `<section>` 之外的部分（`<html>` 外壳、`.v-demo` 包裹）都属于预览脚手架，**不要复制进业务代码**

## 8. 预览机制与限制

### 可用的三种看法

| 方式 | 怎么做 | 适合 |
|---|---|---|
| 独立打开 | 双击 `tools/variants/<变体>.html` | 最终验收、给设计/业务看 |
| 内嵌在业务页 | 项目里直接引 CSS + 复制结构 | 验证真实数据下的表现 |
| **总览页**（推荐） | 双击 `tools/设计规范总览.html` | 一次看全部组件 + 全部变体，改 token 立刻传导 |

三种看法都能用，但日常检查只需总览页一个：变体是以**内联**方式嵌进去的（不是 iframe），所以改 token 后所有变体同步变化，一眼就能看出改规范有没有波及布局。

### token 联动

变体页面 `<link>` 的就是真实的两份 CSS，所以：

```
改 assets/design-tokens.css 或 patterns.css
        ↓
刷新变体页 / 画廊 → 立刻看到新效果
```

**不会自动热更新**：`file://` 协议下浏览器不允许页面主动读取本地文件变化。想自动刷新需要起一个本地 HTTP 服务，属于可选增强，不是必需。

### 已知限制（都是真的，别踩）

1. **变体不再需要单独登记到清单**。总览页构建时自动扫 `tools/variants/` 目录，只认文件本身；登记表只负责 P 编号与「适用/不适用」的说明，漏登记也不会从页面上消失（会退回用文件名当标题）。

2. ~~语义色没进 token~~ **已修复**：`--success/--error/--warning/--info/--geekblue/--processing/--purple` 已补进 `design-tokens.css`，变体可以直接用语义色做校验错误态与状态标签。

3. **纯复制没有版本约束**。变体升级到 1.1.0 后，已经复制走的老页面不会自动更新。建议在业务项目里维护一份引用清单（哪个页面用了哪个变体、哪个版本），否则升级等于盲改。

4. **交互型变体超出本机制**。折叠展开、字段联动、实时校验这类需要 JS 行为，纯 CSS + 静态 HTML 表达不了。这类变体要额外附一份「行为契约」（什么事件、什么状态、什么过渡），否则复制走只有外观没有行为。

5. **字体依赖本机安装**。规范用 Source Han Sans CN / DIN Alternate，没装的机器会回退到系统字体，预览和实际效果会有差异 —— 这是字体授权问题，不是规范问题。

6. **白色容器面没有 token**。`design-tokens.css` 里 `.card` 本身就是直接写 `background:#fff`，没有 `--surface-card` 之类的变量。变体沿用同样写法保持一致，目前 `patterns.css` 里的硬编码只剩这一种白。后续若要统一，先补 token 再一起替换。
